## 1. What counts as a guard, and what was scanned

A guard is region-threading code that **disables, refuses, reroutes or degrades** behaviour. The policy
script scans the Minecraft/Paper Java files touched by the engine baseline patches **and** by the
SourbyCraft feature patches (a guard a feature patch adds or rewrites is recorded with its marker's
origin; `patch_policy.py` checks containers, defaults, compression and collision bounds, not guard
shapes, so nothing else would see it), plus the engine sources SourbyCraft owns outright
(`sourbycraft-server/src/main/java/dev/iyanz/aurora/engine`). It reads the materialized sources when
they exist and otherwise the post-image of each patch hunk, hunk by hunk (a marker in one hunk never
vouches for a line in another; only added lines are candidates; lines a feature patch deletes are
subtracted) — both modes find the same set
(`RepositoryTest.test_patch_scan_matches_the_materialized_scan`). Lines are matched on a code view
with string contents and comments removed, block comments included when they span lines, so a
commented-out method or a message text is never a guard, and a condition counts as constant only
when it is (`true`, `((true))`, `false && ...`, `true || ...`; `true && enabled` is not).

Detectors: **A** a constant `if` with a `// Folia`, `// Canvas` or `// SourbyCraft` marker (or a region
throw) within 3 lines before / 2 after or inside a `// X start` block, unless the `if` line credits
another project; **B** `throw new UnsupportedOperationException(...)` with a region message, a marker
on the line, or inside a `// X start` block — and, since the owned messages landed, `throw
dev.iyanz.sourbycraft.guards.RegionRefusal.X.error()`; **C** in the engine-owned packages
(`io/papermc/paper/threadedregions/`, `dev/iyanz/aurora/engine/`) every constant `if` and every
refusal-shaped `UnsupportedOperationException`; **D** `@Unsupported` (`dev.iyanz.sourbycraft.api.Unsupported`) annotations in
the API; **E** a marked constant early return that is the first statement of a method. Plus five
**ownership-check families** counted by marked call site rather than enumerated (section 4).

**Kinds**: `FEATURE-DISABLED` (a vanilla/Paper feature is off), `API-REFUSED` (a Bukkit, Paper or NMS
entry point throws), `OWNERSHIP-CHECK` (a region-ownership assertion), `DEGRADED` (works, with
something lost), `REROUTED` (behaviour kept through a region-safe path; listed because the scanner
cannot tell the shapes apart and so the ledger stays complete). **Decisions**: `KEEP-OWNED` (the guard
protects a correctness invariant, or an owned replacement now stands behind it; the note says which
and names the test or says "test missing"), `REPLACE` (SourbyCraft should implement the behaviour
region-safely; design sketch and risk in the note), `REMOVE` (dead), `UNDECIDED` (what must be checked
is recorded). **Origin** is the project named by the nearest marker; a line SourbyCraft rewrote in
place keeps its inherited origin and says so in its note; without any marker the recorded origin
stands.

**Deliberately excluded** (reasons, so nobody re-audits them): Paper's own `if (true)` lines
(`PaperAdventure.asVanilla`, chunk-system rewrite returns, the `HorriblePlayerLoginEventHack:59`
warning downgrade — the file's only history is the upstream import, so it is Paper's; `Metrics:101
if (false)` whose surrounding comment carries no marker — its sibling `Metrics#1` is recorded); plain
`throw new UnsupportedOperationException()` without a message in `RegionizedTaskQueue` (read-only
collection views, not guards); engine-source throws whose message is a parser type check rather than
a refusal (`ConfigurationProvider`/`NodeDiff`/`Token` "must be a MappingNode"); `return;` as the
first line of an `if (!TickThread.isTickThreadFor(...))` block (that is the ownership family, section
4, not a separate guard); code inside `/* ... */` (`ThreadedRegionizer.loadTestData`, retired once the
scanner understood block comments); and features Canvas **rewrote** rather than guarded (`/datapack`
is read-only — `DataPackCommand` "Canvas start" block; the waypoint manager, whose
`RegionizedWaypointManager` is what runs), which are described where a detected guard touches them.

## 4. Ownership-check families (KEEP-OWNED)

These are the invariant itself, not features: code that mutates an entity, chunk or world slice must
run on the thread that owns it. SourbyCraft adopts the rule as its own (DEVELOPMENT.md: region
ownership outranks throughput) and already writes new checks in the same style (feature 0016,
`SourbyReply.hopFor`). Counts are of sites that carry a `// Folia` / `// Canvas` marker; Paper's own
`TickThread` checks (70 `ensureTickThread`, 105 `isTickThreadFor`, 46 `AsyncCatcher`) are Paper's
and are not counted. The counts are pinned by the manifest; a change is a reviewed regen.

| family | sites | what it is | owned test |
| --- | --- | --- | --- |
| `F-TICKTHREAD-ENSURE` | 201 | `TickThread.ensureTickThread`: throws `IllegalStateException` off the owning thread; not configurable | count only; per-site tests missing |
| `F-TICKTHREAD-IS` | 46 | `TickThread.isTickThreadFor`: picks a region-safe branch | count only |
| `F-GLOBAL-TICK` | 29 | `RegionizedServer.ensureGlobalTickThread`: global state (scoreboards, world list, status, time) | `AuroraWorldsService` tests for SourbyCraft's own callers |
| `F-TICKGUARD` | 17 | Canvas's configurable guards: `region-scheduler.guard-severity` (SourbyCraft default `LOG`, Canvas shipped `THROW`); with `LOG` a hit inside a bridged plugin's task counts toward its quarantine | `scripts/test_patch_policy.py` (LOG default), `ViolationClassifierTest`, bridge `GuardViolations` tests |
| `F-ASYNCCATCHER` | 0 | Paper `AsyncCatcher` sites re-marked by the engine: the two marked calls are commented out, so the engine's own checks replaced them entirely; pinned at 0 so a re-marked site is noticed | count only |

Paper API and the family is re-decided. `PacketUtils.ensureRunningOnSameThread` (62 sites, vanilla)
is not a guard: the engine's version reroutes packets to the player's region queue instead of

## 8. Keeping this ledger honest

```bash
python3 scripts/inherited_guard_policy.py                   # exit 1 on an unrecorded/undecided guard or count drift
python3 scripts/inherited_guard_policy.py --write-manifest  # regenerate; decisions of unchanged entries are kept
python3 scripts/inherited_guard_policy.py --write-manifest --allow-removals   # also drop entries that vanished (listed)
python3 scripts/inherited_guard_policy.py --summary         # the generated numbers block in section 1
python3 scripts/inherited_guard_policy.py --markdown        # the appendix table below
python3 -m unittest discover -s scripts -p 'test_inherited_guard_policy.py'
```

The manifest key is `file + site + anchor + n-th identical anchor at that site`, where `site` is the
two nearest preceding non-blank lines (for an annotation, the declaration it annotates) with
SourbyCraft-inserted lines skipped for an inherited guard, so neither line drift nor applying a
feature patch above a guard re-keys it; a line SourbyCraft rewrote in place (an owned refusal message)
is keyed like SourbyCraft's own code. `method` (the enclosing method when its header is in view) and
`line` are informational, except that for guards which share a site a recorded method that no longer
matches fails the check and blocks the carry-over, so reordering methods cannot silently swap two
decisions. A new guard, a vanished guard, a changed family count or a missing decision fails the
check. `--write-manifest` keeps decisions by key, refuses to drop vanished entries unless
`--allow-removals` is given (they are listed), never touches a manifest that does not parse, never
renames or reuses an id, and migrates a pre-`site` manifest once by `file + anchor + occurrence` (the
check says so until it is done). A re-worded guard (same method, new anchor) is a removal plus a new
entry: carry its decision by hand, as this round did for the 26 owned-message refusals. The
repository tests run in the pull-request job (patch-mode scan; the materialized/patch equivalence test
skips there with its reason, no `pr_checks.py` entry needed). In patch mode a baseline guard that a
feature patch deletes is subtracted by its pre-image key (or by anchor when unique in the file), so
both modes agree after a replacement lands. When a REPLACE lands, its guard entry moves to
KEEP-OWNED (the owned implementation now exists and the baseline guard is bypassed or kept as the off
switch) or the feature patch deletes the baseline lines and the manifest is regenerated with
