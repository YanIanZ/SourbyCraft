# SourbyCraft 26.2 Build 48.1 — hotfix of Build 48 (Aurora Nexus)

Status: hotfix release `v26.2-r48.1` (`release=true`), published from the branch `hotfix/26.2-r48.1`  
Base: `v26.2-r48` (commit `001b86f1`) plus the commits listed below, nothing else from `26.2`  
Signing: same as Build 48 — Ed25519 jar signature, signed release manifest, GitHub build-provenance

Java: 25 · Minecraft: 26.2 · Engine: Aurora Engine

Build 48.1 changes no server behaviour. It fixes what the published file contains.

## Why: the released jar did not carry its licence (SEC-13)

SourbyCraft is GPL-3.0-only since Build 48. The file servers download, `SourbyCraft-26.2-REL.jar`
(the launcher jar), had no `META-INF/licenses/`: its only readable licence was the launcher's MIT
`LICENSE.txt`. The GPL text (`LICENSE_SOURBYCRAFT`), the source notice (`NOTICE_SOURBYCRAFT`) and the
upstream licence texts existed only inside the patched server jar the launcher writes on first boot,
so the distributed binary did not carry the licence and source offer GPL-3.0 section 6 asks for. The
notice also said "This jar does not contain the Minecraft server", which is false for the patched
server jar where it sat. Evidence: the v26.2-r48 REL jar (sha256 `abb1ae6b…`, equal to the published
`.sha256`) listed with `unzip -l`, and a first boot of it (agent evidence 2026-10-22,
`licence-and-cache-2026-10-22.md` part A, Build 49 work; not part of this hotfix).

## What changed

- `slimServerJar` writes every file of the server's `META-INF/licenses/` into the launcher jar, in the
  same sorted entry order with the fixed `SOURCE_DATE_EPOCH` time, so the jar stays reproducible.
- `NOTICE_SOURBYCRAFT` distinguishes the launcher jar (no Minecraft server code) from the patched server
  jar (contains Minecraft code, which stays under Mojang's terms).
- `verify_build_identity.py --licences --source-root .` runs on the launcher jar in CI: the GPL text
  (pinned hash), the notice markers, and byte equality with the checkout's licence directory.
- Release pipeline support for hotfix branches (also on `26.2`): `hotfix/26.2-r<N>.<M>` publishes
  `v26.2-r<N>.<M>` through the same jobs; see `docs/development/AUTO-UPDATER.md`, "Hotfix releases".
- `sourbyBuild=48.1`.

## Identity and the auto-updater

`/ver` and the startup banner say `Build 48.1 — Aurora Nexus`; `sourbycraft-build.properties` has
`buildNumber=48.1`. The manifest `Build-Number` stays `48` because Paper parses it as an integer, so
`Bukkit.getVersion()` reads `26.2-48-…` as on Build 48. The auto-updater orders `48 < 48.1 < 49`:
Build 48 servers are offered 48.1 (installed only where `apply-mode = "auto"`), and the next 26.2
release (Build 49) supersedes it.

## Not in this hotfix

Everything merged to `26.2` after `v26.2-r48` (#27–#30 and later: Build 49 configuration layout, bench
tools, rebase tooling). Those ship with Build 49.
