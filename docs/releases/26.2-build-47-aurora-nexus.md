## Release pillars
- Aurora Compatibility Bridge
- Aurora Instant Startup Cache
- Aurora World Fabric
- Aurora Execution Fabric and Resource Governor
- Network/storage observability
- Structured startup and plugin diagnostics

## Safety order
Correctness > reliability > data safety > stability > compatibility > tail latency > resource efficiency > startup performance > scalability > throughput.

## Public identity
Public branding is **SourbyCraft 26.2 Build 47 — Aurora Nexus**. Paper, Folia, Canvas, Moonrise and AdvancedSlimePaper are implementation/provenance inputs, not public build suffixes.

## Mandatory release gates
Build 47 MUST NOT be declared STABLE until compile, unit/integration, patch regeneration, plugin compatibility, region ownership, world load/unload/save, crash recovery, cache corruption, backend failure, startup, stress, soak and shutdown qualification pass.

## Core contracts
- no expensive CallerRuns fallback onto region owners;
- no unbounded executor queues;
- no blocking filesystem/database work on region threads;
- no worker mutation of live region-owned state;
- no startup cache containing live runtime objects;
- no compatibility color/status stronger than observed runtime evidence;
- no release-wide performance percentage without comparable certified evidence.

## Implementation status

Status is per pillar and reflects code on the `26.2` branch, not qualification. "Unit-tested"
means JUnit coverage of the new classes run on Java 25; none of the rows below has been through
the mandatory release gates above, and the full server build (which needs the private toolchain)
has not been run for this change.

| Pillar | State | What exists | What does not |
| --- | --- | --- | --- |
| Aurora Compatibility Bridge | PARTIAL | `bridge.CompatibilityState`/`CompatibilityClassifier`; `/plugins` colours by NATIVE/BRIDGED/FAILED/DISABLED; enable failures captured from Paper's log line | No bridge adapter. The region-threading base still refuses plugins without `folia-supported`/`canvas-supported`, so BRIDGED is unreachable. No routing, quarantine or per-plugin redirect telemetry |
| Aurora Instant Startup Cache | PARTIAL | `startup.*`: SHA-256 source fingerprints, environment key (MC/Sourby ABI/Bridge ABI/format/Java), per-entry integrity, WARN-once discard and rebuild, atomic write, bounded `STARTUP` lane, hit/miss/discard telemetry; first consumer is the plugin descriptor index (boot stage `startup index`, `/sys` line) | Class index, transform outputs, dependency graph and AWF indexes are not cached. The index is diagnostic: it does not speed up plugin loading, and no cold/warm startup benchmark exists |
| Aurora World Fabric | FOUNDATION | `awf.WorldRole`; `awf.GenerationStore` — FILE-backend atomic generation commit (snapshot → temp → verify → CURRENT pointer), crash recovery on open, retention, region-thread refusal, `commitAsync` | Not used by any world. No MongoDB/MySQL/Redis, INCREMENTAL/CHECKPOINT, lazy materialisation, copy-on-write templates or AWF metrics |
| Execution Fabric / Resource Governor | NOT STARTED | Existing lanes plus a `STARTUP` lane attribution | Everything in the pillar |
| Network/storage observability | NOT STARTED | — | — |
| Structured startup and plugin diagnostics | PARTIAL | Boot stage `startup index` logs jar count, start class and cache counts, and warns before plugin load about jars the base will refuse | No per-phase plugin load/enable timing |

Operator switches added: `-Daurora.startup.cache=false` (RESTART_REQUIRED) disables reading and
writing `sourbycraft_config/cache/startup-index.cache`; the analysis still runs.
