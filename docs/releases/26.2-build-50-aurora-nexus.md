### Operator-visible changes in the candidate (not in `v26.2-r50`)

- **AWF:** an unconfirmed final commit at unload completes as FAIL_UNKNOWN with an ERROR and the server
  keeps running; `AuroraWorlds.unload(save=true)` refuses the unload when its durable save fails; a load
  is refused when a store the registry recorded is missing; vanilla dimension names and the level-name
  are refused as AWF world names; a stored pre-Build-50 spawn the new validation refuses is dropped with
  a WARN. READ_ONLY and TEMPLATE opens of FILE stores no longer run crash recovery, temp cleanup or
  directory creation; failures of post-commit cleanup (generation prune, object collection) are WARNs
  (at most one a minute per store), retried by the next commit. `/awf import` restores Slime plugin
  data. New `/perf awf` rows: oldest dirty age, loaded AWF worlds, refused writes, AWF Redis leases.
  `/awf delete`, `import`, `export`, `convert`, `clone`, `set`, `template delete` and `unload … nosave`
  also check `sourbycraft.command.awf.admin` (implied by the command node unless set explicitly).
- **AWF Redis:** an invalid `aurora.awf.redis.uri` or `SOURBYCRAFT_AWF_REDIS_URI` refuses the backend
  and the fabric instead of falling back to `redis://127.0.0.1:6379/0`; Redis worlds then fail to load
  until the URI is fixed.
- **MultiProfile:** armor and off-hand belong to a profile only under `isolation.armor`; with
  `isolation.location` a switch sets or clears the respawn point (restored as a forced one); the first
  switch archives the pre-profile state; new admin subcommands `lock`, `slots`, `owner`, `reclaim`,
  `migrate-repository`.
- **Updater:** a failed apply preflight or swap no longer restarts the server; it logs the manual steps
  and writes `auto_update/apply-failed.tag`. The swap is atomic, releases for another Minecraft version
  are only announced, the rollback guard runs first at boot, and a rollback to a pre-49 jar restores its
  `*.migrated` TOML and canvas config files.
- **Provisioning:** a group whose file sets only the pre-49 `<group>.auto-provision` key, an invalid or
  flow-style value, or an unreadable file skips provisioning for that boot (nothing downloaded,
  installed or quarantined); the pre-49-only case repeats every boot until
  `plugins.<group>.auto-provision` is set.
- **Configuration:** old names are no longer read (table below); one WARN per unknown key and per
  `*.toml` left beside its `*.yml`; duplicate YAML keys are refused; `/sourbycraft reload` runs off the
  tick thread.
- **Telemetry and UX:** `/bukkit:version` hover and clipboard show JVM option names only; sizes print with
  two decimals; `/perf cpu` says "live Java threads"; `/perf async` gains a `declined` row and delivery
  outcomes; the release-stage colour follows the table under *Publication stage*.
- **Bridge:** relaxed-mode lines are logged once per plugin and reason per 60 s; a repeating bridged
  async timer keeps at most one queued run and skips (instead of cancelling) a run over
  `max-running-async-tasks-per-plugin`.
- **SourbyMod:** mods load in file-name order; `onUnload` runs at shutdown for every loaded mod.

### SourbyMod (ML1)

`mods/*.jar` with a `sourbymod.yml` at the root are loaded in their own `URLClassLoader`
(parent = server classloader, so NMS + Bukkit + `dev.iyanz.sourbycraft.*` are visible), in file-name
order on the candidate. `onLoad` runs in the `sourby mods` boot stage after configuration and before
worlds; `onEnable` runs on `ServerLoadEvent(STARTUP)`; at shutdown `SourbyCraftBootstrap.close()` calls
`onDisable` (if the mods were enabled) and, on the candidate, `onUnload` for every mod whose `onLoad`
succeeded, in reverse order. A broken mod is isolated (WARN, server continues), duplicate ids and
`api > 1` are skipped, and descriptor parsing uses SnakeYAML `SafeConstructor`. The loader is **not**
a Fabric/Forge loader: those jars are refused with one WARN each. Format and limits:
[`docs/SOURBYMODS.md`](../SOURBYMODS.md).

Owner testing handbook: [`docs/testing/owner/00-TESTING-INDEX.md`](../testing/owner/00-TESTING-INDEX.md).
Historical owner reports remain recorded there; affected candidate cases are `NEEDS RETEST`.
