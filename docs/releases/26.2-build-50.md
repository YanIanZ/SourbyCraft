## Theme

Certified baselines first, then measured optimizations in the entity, chunk and network domains,
the async pathfinding default decision, and memory/allocation work. Every performance statement
follows [docs/DEVELOPMENT.md](../DEVELOPMENT.md#3-performance-claim-requirements): commit/build,
workload, hardware, thread/worker/config values, world state, client fidelity, window,
certification state, metric and statistic.

## Entry criteria

- Build 49 tagged. Certified references are taken on the Build 49 tree; optimizations are
  compared against them.
- A quiet machine meeting the certification rule (foreign CPU below 10 % for the whole window,
  `docs/architecture/qualification-readiness.md` §6). None exists on 2026-10-21; four attempts in
  September measured 21–23 % average.
- Real clients available for `players-*` and `entity-stress` (entity activation is computed around
  players; driving mobs without players measures the inactive path).
- Owner decision on the representative product workload.

## Rules

- Regression gate (docs/DEVELOPMENT.md §7): unexplained >3 % regression → investigate; >5 % → written
  justification; >10 % → blocks unless it fixes a correctness/security defect.
- Stability budget (docs/DEVELOPMENT.md §6) holds for every optimization; a change touching
  concurrency or lifecycle needs a soak.
- No default changed for performance without certified A/B evidence (ENG-9 rule); no gains from
  reduced gameplay work (docs/DEVELOPMENT.md §5); no thread-count folklore (§6).
- Uncertified runs may guide work but are labelled uncertified and support no release-wide claim.

## Canvas-era name removal (deprecation schedule)

Owner decision 2026-10-21: every remaining user- or plugin-visible Canvas identifier was renamed in
Build 48; the old names are still read, with a deprecation warning, through Build 49 and are
**removed in Build 50**. Every fallback goes through `dev.iyanz.aurora.engine.util.LegacyNames`
(`REMOVAL_BUILD = "Build 50"`), so removing it is: delete the fallback branch at each call site below,
delete the tests named, and change their docs to "removed".

| Old name | New name | Fallback to delete in Build 50 | Tests to update |
| --- | --- | --- | --- |
| `-DCanvas.AggressiveChunkSystem` | `-DAurora.AggressiveChunkSystem` | `LegacyNames.flag(...)` in `MoonriseCommon.java.patch` (Paper engine baseline) | `LegacyNamesTest` |
| `-DCanvas.DisableRegionProfiler` | `-DAurora.DisableRegionProfiler` | `LegacyNames.strictFlag(...)` in `SchedulerUtil.java.patch` (MC engine baseline) | `LegacyNamesTest` |
| `-DCanvas.isRunningInIDE` | `-DAurora.isRunningInIDE` | `LegacyNames.flag(...)` in `SharedConstants.java.patch` (MC engine baseline) | `LegacyNamesTest` |
| permission `canvas.broadcasting.receiver` | `aurora.broadcasting.receiver` | `BroadcastPermission.LEGACY_NODE` branch | `BroadcastPermissionTest` |
| `Canvas.Distance` key in `paper:level_overrides` | `Aurora.Distance` | legacy branch of `PerWorldDistanceConfig.LEVEL_OVERRIDES_FIELD` / `fromRawLevelData` | `PerWorldDistanceLegacyKeyTest` |
| `data/canvas/pearls.dat` (`canvas:pearls`) | `data/aurora/pearls.dat` (`aurora:pearls`) | the Canvas-era branch of `PearlsMigration` (a world first started on Build 50 would then ignore an unmigrated `canvas/` file: keep it until the owner accepts that, or keep the read-only migration) | `PearlsMigrationTest`, `AuroraFileMigrationTest` |

Removed in Build 48 without a deprecation window (owner decision): `ServerBuildInfo.BRAND_CANVAS_ID`
(breaking API change, `sourbyapi/README.md`), the dormant `/canvas` command code with its
`canvas.command.*` permissions and `-DCanvas.LegacyHelpCommand`. Renamed with no old-name reader because
nothing persisted or external depends on them: ticket types `aurora:end_credits` /
`aurora:region_profiler_hold` (not persisted), bStats names (nothing submitted), the Spark config group
`aurora/`, the GUI icon, `AuroraVersionFetcher`, `AuroraFileMigration`.

Kept deliberately, not on this schedule: `config/canvas-server.yml`, `config/canvas-worlds.yml`,
per-world `canvas-patch.yml`, the plugin.yml key `canvas-supported`, and
`META-INF/licenses/LICENSE_CANVAS`.

| Gate | State | Evidence required |
| --- | --- | --- |
| Canvas-era fallbacks removed | NOT RUN | the six fallbacks above deleted, their tests changed to assert the old name is ignored, boot log of a Build 50 jar shows no `deprecated` line for them |
