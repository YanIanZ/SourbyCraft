## Theme

Certified baselines first, then measured optimizations in the entity, chunk and network domains,
the async pathfinding default decision, and memory/allocation work. Every performance statement
follows [docs/DEVELOPMENT.md](../DEVELOPMENT.md#3-performance-claim-requirements): commit/build,
workload, hardware, thread/worker/config values, world state, client fidelity, window,
certification state, metric and statistic.

## Entry criteria

- Build 49 tagged. Certified references are taken on the Build 49 tree; optimizations are
  compared against them.
- A quiet machine meeting the certification rule (foreign CPU below 10 % for the whole window,
  `docs/architecture/qualification-readiness.md` §6). None exists on 2026-10-21; four attempts in
  September measured 21–23 % average.
- Real clients available for `players-*` and `entity-stress` (entity activation is computed around
  players; driving mobs without players measures the inactive path).
- Owner decision on the representative product workload.

## Rules

- Regression gate (docs/DEVELOPMENT.md §7): unexplained >3 % regression → investigate; >5 % → written
  justification; >10 % → blocks unless it fixes a correctness/security defect.
- Stability budget (docs/DEVELOPMENT.md §6) holds for every optimization; a change touching
  concurrency or lifecycle needs a soak.
- No default changed for performance without certified A/B evidence (ENG-9 rule); no gains from
  reduced gameplay work (docs/DEVELOPMENT.md §5); no thread-count folklore (§6).
- Uncertified runs may guide work but are labelled uncertified and support no release-wide claim.
