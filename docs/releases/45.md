# SourbyCraft 26.2 — Build 45c, Aurora

Build 45 integrates Claude's committed Phase 0/1 work and a follow-up review of its baseline comparison gate.

- Remove shared ServerLevel scratch collections from patches 0013 and 0015. Concurrent region ticks now use the upstream per-call collections again.
- Publish a detached immutable particle list only when effect particles change. Reusing the published list previously prevented synchronization from detecting changes.
- Move RegionTickMetrics into SourbyCraft's own source tree; keep the upstream metrics integration patch small. Existing TickData compatibility checks remain in the test suite.
- Add workload/JFR baseline capture, metric extraction, comparison tooling, and patch/threading inventories.
- Fix baseline comparison to reject uncertified inputs, avoid a PASS verdict under provenance drift, and compare the captured network throughput field.

Java 25 is required. This release retains the operator's configuration and does not automatically tune heap, GC, or gameplay settings. Release identity advances from 44 to 45; manifest and properties both derive from sourbyBuild.

## Validation and limits

CI must pass patch regeneration, API/server tests, boot/JFR, and Docker checks before automatic publication. Scratch-buffer tests cover ownership/publication constraints; baseline comparison regressions have dedicated Python tests.

The baseline harness is initial instrumentation, not proof of a performance improvement. Player workloads require external connected clients; status-protocol network load does not simulate gameplay. Controlled before/after workload runs and multi-hour soak remain outstanding. See [baseline instructions](../BASELINE.md), [threading review](../architecture/threading.md), and [build 44 scope](44.md).
