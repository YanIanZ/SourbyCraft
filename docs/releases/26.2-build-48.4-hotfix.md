# SourbyCraft 26.2 Build 48.4 — hotfix (Aurora Nexus)

Release source: `hotfix/26.2-r48.4`, based on `v26.2-r48.3` (`0d544f27`).
Publication requires the official build, boot and independent reproducibility jobs to pass.
Java: 25 · Minecraft: 26.2 · Engine: Aurora Engine. No STABLE claim.

## Changes

- A synchronous chunk load requested from the region shutdown thread is refused up front with an owned
  message. The scheduler halts before plugins disable, so a load scheduled from a plugin's `onDisable`
  can never run: pumping the main-thread queue threw `Polling tasks from non-owned region` (r48.3),
  and waiting for the load hung the shutdown (boot probe). An already loaded chunk still serves the
  write. Feature patch 0081 (Minecraft commit `6c2a268`).
- The BRIDGE_IO lane reporting `full or stopping` no longer logs a WARN with a stack trace per skipped
  repeating task during shutdown: a stopped lane says `BRIDGE_IO lane is stopping`, keeps the
  per-plugin rate limit, and logs no throwable. Saturation keeps its WARN and also drops the throwable.
- An unreadable config file is reported as `file (near line N: snippet): parser message` by the bridge,
  AWF, Redis, chunk-generation and `SourbyCraftConfig` readers, instead of a token with no location
  (`Invalid integer: sourby`). Values and files are never rewritten by the diagnostic.
- The legacy test fixture writes an unloaded chunk from `onDisable`; the bridge boot requires the
  refusal marker and fails on `Polling tasks from non-owned region`.

The hotfix backports only these changes. Build 49 configuration renaming, the TOML→YAML migration,
console changes, background level.dat writer and Build 50 hook refactors are excluded. The portable
port's MC 0084–0086 remain 0078–0080 on this base. Build 48 configuration files keep their layout.

## Operator behavior

No configuration key is added or renamed. `aurora.bridge.mode` still defaults to `off`; with
`mode = "safe"` the 2026-10-22 relaxed thread-check default applies as in 48.3.

A plugin that writes to an **unloaded** chunk from `onDisable` now receives an
`IllegalStateException` naming the halted scheduler instead of the bridge/pollTask error; the write
cannot be applied at that point either way. Writes to already loaded chunks are unaffected.

The shutdown log is quieter: one rate-limited stopping line per plugin instead of a stack trace per
skipped run. Diagnostic-only; scheduling behavior is unchanged.
