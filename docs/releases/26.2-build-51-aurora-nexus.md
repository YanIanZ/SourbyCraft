### 3. Co-op MultiProfile foundation (slices 2+3, G1)

Design: [COOP-DESIGN.md](../awf/multiprofile/COOP-DESIGN.md). **MultiProfile stays off by default.** With it
off, none of the following code runs.

- **Record format 2** for FILE and Redis. Each write is checked against four independent revision domains
  (account, profile metadata, shared state, per-member snapshot head) and against a typed claim, either a
  profile claim or a player session claim. Redis checks claim and revisions in one Lua script before the first
  write. FILE does a compare-and-set under the directory lock.
- **Intents.** Multi-record changes (profile create and delete) go through prepare → commit with staged
  after-images. Recovery runs after a crash at any phase. A lost reply resolves to COMMITTED, REPLAYED or
  **UNKNOWN**, and an UNKNOWN outcome is never treated as success. Redis also requires `WAITAOF` confirmation
  when `redis.wait-for-aof` is on.
- **Migration from format 1 to 2** (`aurora.awf.multiprofile.migration.mode: off|dry-run|apply`, default `off`,
  RESTART_REQUIRED). `apply` needs `migration.backup-dir`, writes a verified backup first, and can resume after a
  crash. `dry-run` writes nothing and refuses a store it could not migrate. All nodes must be stopped first,
  because Redis has no migration lock.
- **Downgrade gate (OD-2).** A format-2 store is one-way. The Build 51+ auto-updater refuses to restore or apply
  a build below 51 when the configured store is format 2. Builds before 51 have no gate of their own: **never
  start them on a migrated store.** The only way to downgrade is to restore the pre-migration backup into an
  isolated store.
- **Profile names and types.** Every profile gets an immutable name from the fruit/vegetable pool, unique per
  account, ignoring case. A profile also has a type (`classic`, `ironman`, `stranded` or `bingo`;
  `types.allowed`, `types.default`). In Build 51 the type is stored and shown, but no type rule is enforced
  (that is Build 55). A format-1 store keeps Build 50 behaviour. On such a store, creating a profile with a
  name or with a non-`classic` type is refused with `MIGRATION_REQUIRED`.
- **API (binary compatible).** New: `ProfileType`, `ProfileDetails`, `AuroraProfiles.getProfileDetails` /
  `listProfileDetails`, and `ProfileRequest` name/type. New `ProfileErrorCode` values (`NAME_TAKEN`,
  `NAME_INVALID`, `TYPE_NOT_ALLOWED`, `STORE_FORMAT_REFUSED`, `MIGRATION_REQUIRED`, `COUNTER_EXHAUSTED`,
  `CLAIM_LOST`, `UNKNOWN_OUTCOME`, `CAPACITY_EXCEEDED`) are appended at the end, after the existing values.
- **Commands.** `/awf multiprofile create <player> [namespace] [type=…] [name=…]` is new. `info`/`list` show the
  name and type. `format` and `migrate <dry-run|apply>` need `sourbycraft.command.awf.admin`. `migrate apply` at
  runtime only explains how to migrate: the migration runs at startup.
- **On a format-2 store** every join first takes the player's session claim. If another live session holds it,
  the player is disconnected with a reason. A player whose session claim is confirmed lost is frozen and
  disconnected.
- **Co-op membership is not available yet.** Invites, votes, kicks and salvage records exist in the format, but
  no command or API exposes them. Membership comes in Build 52.

## Owner test cases

The unit test sources were written by agents and **never run by them**. CI runs them on push.
- `CoopSlice2Test`, `CoopFormat2RecordsTest` (golden bytes), `CoopFileRepositoryTest`, `CoopRedisTest` (skips
  without `redis-server`), `CoopNamesAndTypesTest`, `CoopMigrationTest`.
- Case names follow COOP-DESIGN §10 slices 2 and 3.

Manual cases:
- **TO-B51-01:** a format-1 store with migration off behaves exactly like Build 50 (MP-001…009).
- **TO-B51-02:** dry-run on a copy of a real store reports counts and writes nothing.
- **TO-B51-03:** `apply` creates a backup, kill -9 mid-migration, restart, and the migration resumes.
- **TO-B51-04:** after migration, create/switch/save/quit/login, plus kill -9 during a create.
- **TO-B51-05:** Redis variant of 02–04 with `wait-for-aof` on.
- **TO-B51-06:** the updater refuses a Build 50 jar on a format-2 store, and accepts a same-or-newer jar.
- **TO-B51-07:** names are unique per account and immutable. Types `allowed`/`default` are honoured.

## Known limits

- The open Build 50 gates (PM-028, PM-076, PM-091, PM-456, distributed live state, and the others listed in
  the readiness doc) are unchanged.
- The FILE backup lookup on resume compares file sizes, not digests (documented in `FileProfileBackup`).
- A Redis migration checks only for nodes that hold a claim at that moment, so the operator must stop every node.
