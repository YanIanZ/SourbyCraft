# SourbyCraft 26.2 Build 48 — Aurora Nexus

Status: FULL RELEASE by owner decision 2026-10-22 (`release=true`), **not** labelled STABLE — the
STABLE label stays reserved for Build 49 ([ROADMAP-47-50.md](ROADMAP-47-50.md))  
Target channel: full release (`release=true`); servers with the auto-updater on `apply_mode=notify`
(the default) are told about it, servers still on `auto` install it  
Signing: **signed** — first release signed with the SEC-2 Ed25519 release key (fingerprint
`sha256:a9643e8b3dcdaae50d0acd5a93f4ef1fff593ee7c8bf26199ca32a0b7232f9c4`; public key in the jar at
`META-INF/sourbycraft-release.pub`); the release also carries a GitHub build-provenance attestation and a
CycloneDX SBOM  
Java: 25 · Minecraft: 26.2 · Engine: Aurora Engine

Build 48 is the refinement release of the 47–50 plan: it replaces inherited Canvas/Folia guards with
SourbyCraft-owned behaviour, restores vanilla features region threading had switched off, removes the
CanvasMC plugin API and names, and adds the diagnostics real testers of Build 49 need. Everything below
is verified by unit/integration tests and short local functional boots on the agent test server. None
of it is qualified, and no performance claim is made. Real-server, real-player testing is owner-run.

## Breaking changes for plugins

- **`io.canvasmc.*` plugin API removed, no shim.** The former Canvas API is
  `dev.iyanz.sourbycraft.api.*` (`event`, `event.world`, `region`, `simd`, `Unsupported`,
  `world.WorldUnloadResult`). Plugins compiled against `io.canvasmc` must be rebuilt
  ([sourbyapi/README.md](../../sourbyapi/README.md)).
- **`ServerBuildInfo.BRAND_CANVAS_ID` removed**; `BRAND_SOURBYCRAFT_ID` (`sourbycraft:sourbycraft`) is
  the brand id.
- Deprecated names still read until Build 50 with a deprecation WARN (once per name; the permission once per holder): JVM flags `Canvas.*`
  (now `Aurora.*`), permission `canvas.broadcasting.receiver` (now `aurora.broadcasting.receiver`),
  level override `Canvas.Distance` (now `Aurora.Distance`). `canvas:pearls` data is migrated once to
  `data/aurora/pearls.dat`. Kept on purpose: `config/canvas-*.yml` file names and the
  `canvas-supported` plugin.yml key.

## What changed since Build 47

Owned behaviour replacing inherited guards (the [inherited-guard ledger](../architecture/inherited-guards.md)
now records a decision for every guard; 118 remain, none UNDECIDED):

- **Command blocks** run under region rules (MC 0055), `aurora.world.command-blocks`, LIVE, **default
  off**. Local two-region run: own-region commands run, 19 cross-region command types refused with no
  mutation ([evidence](../development/cmdblock-two-region-2026-10-21.md)).
- **Teleport**: synchronous teleports run on the owning region (MC 0057/0058, Paper 0017,
  JVM property `-Daurora.compat.sync-teleport`, read once at JVM start (not a config key), default on); `PlayerSpawnLocationEvent` on the
  global tick.
- **Ender pearls** fire `PlayerTeleportEvent(ENDER_PEARL)` on the player's region before the transfer;
  cancel and `setTo()` are honoured (MC 0064).
- **Legacy sync events**: `PlayerPreLoginEvent` (MC 0073), `PlayerChatEvent` and Paper's sync
  `ChatEvent` (Paper 0022) fire again for plugins that listen to them.
- **`ServerTickManager`** API works (freeze, step, sprint, rate; server-wide) (MC 0074, Paper 0023,
  sourbyapi 0003). `/tick` stays unregistered.
- **Refusals** of main-thread-only calls name the owned alternative (MC 0061, Paper 0019); work queued
  on the undrained server queue fails loudly (MC 0060).
- **World unload** gives entity tasks their retired callback instead of running their body (Paper 0021,
  ENG-3), and releases bridged plugin tasks anchored to that world.

Vanilla features restored:

- **Datapack functions**: `/function`, `/return`, `#minecraft:load` once per library (MC 0066);
  `#minecraft:tick` only with `aurora.world.tick-functions` (LIVE, default false). `/reload` stays
  unregistered ([datapack-functions.md](../architecture/datapack-functions.md)).
- **`/schedule`** registered and ticked on the global tick (MC 0065).
- **`/data … storage`** works from the console inline and from players/command blocks through the
  global tick; console block data is handed to the owning region (MC 0069).
- **Wandering traders**: one spawner per world on the global tick, timers persisted (MC 0068).

Persistence and shutdown:

- Global-owned level data saved on autosave (MC 0056); forced-chunk tickets saved on autosave (MC 0067).
  Raids and the world PDC stay shutdown-only (no consistent concurrent copy exists).
- **AWF shutdown deadline (D6)**: `aurora.awf.shutdown-deadline-ms` (default 30000, RESTART_REQUIRED);
  an unconfirmed storage logs `AWF-SHUTDOWN-INCOMPLETE` and the stop exits with status 70 (MC 0071).
  The budget includes the vanilla chunk save; very large worlds may need a larger value.
- **`save-all flush` (D4)** says "Saved the game" only after every AWF storage confirmed its commit
  (MC 0072).

Diagnostics and operations:

- **Stall recorder**: when the global tick or a region completes no tick for 10 s, thread dumps, memory,
  cgroup and GC data go to `logs/stalls/` ([STALL-RECORDER.md](../development/STALL-RECORDER.md)).
- `/perf tick` and `/mspt` report a tick still running with its real duration instead of a fixed
  5000 ms.
- `/ver` shows the channel for non-release jars; the manifest `Build-Number` carries the build number
  (Build 47's REL jar printed `26.2-DEV-…` in `Bukkit.getVersion()`).
- Container memory is read from the process's own cgroup; `/sys` shows real RSS and labels heap as heap.
- Startup log uses short `SourbyCraft/<Class>` and `Aurora/<Class>` logger tags.

Build and supply chain:

- Reproducible slim jar from `SOURCE_DATE_EPOCH`; CI rebuilds from a fresh checkout and refuses to
  publish on a hash mismatch; the release job attests the jar and SBOM
  (`gh attestation verify SourbyCraft-26.2-REL.jar --repo YanIanZ/SourbyCraft`).
- SourbyClip 3.1.3: every launcher download has a whole-transfer deadline, a size cap and a bounded
  same-source retry.
- Repository root follows PaperMC/Paper's layout.
